# Crime Map

Карта происшествий Будапешта: лента событий, фотографии, хронология, участники, источники и правовая информация. Интерфейс Crime Map доступен на русском, английском и венгерском.

- **Сайт:** https://crimap.online/
- **GitHub:** https://github.com/Fedorovvn/crimap
- **Ветка:** `main`.
- **Размещение:** собственный VPS, Nginx + Node.js + SQLite.
- **Автоматического деплоя из GitHub нет:** отправка коммитов и обновление работающего сайта — отдельные действия.

Сведения проверены 26 сентября 2026 года. Подробности размещения — в [DEPLOYMENT.md](DEPLOYMENT.md).

## Сборщик новостей и контракт

В редакторе есть сортировка по дате события и поступления, диапазон дат по Будапешту, поиск и совместимые фильтры публикации, проверки текущей версии, раздела, типа, убийств/покушений и последствий. «Опубликованные на сайте» включает все действующие публикации, в том числе с новой неопубликованной редакцией. «Неопубликованные события» — только события, которых нет на сайте; обновления выделены отдельным фильтром. Старые сохранённые значения фильтра совместимы. «Готовы к публикации» учитывает перевод, источники, координаты и успешную проверку Pro.

Настройки ленты сохраняются в localStorage этого браузера; кнопка «Сбросить» возвращает все события и сортировку от новых к старым. Фильтр «Скрыть явно незначительные» использует бесплатные правила, оставляет неясные случаи и ничего не удаляет из базы. Убийства/покушения определяются по тексту и квалификации отдельно от признака «есть погибшие».

Backend находится в `backend/`: RSS/Atom, чтение статей, DeepSeek Flash, проверка DeepSeek Pro, версии событий, EN→RU, возрастной шедулер, журнал расходов и публикация после проверки. Венгерские оригиналы и цитаты сохраняются отдельно. Рабочие данные и ключи не входят в Git.

Редактор событий: **https://crimap.online/admin/**. Вход по приватной ссылке с постоянным токеном в URL-фрагменте: `/admin/#token=…`. Ссылка хранится вне репозитория. Здесь видны черновики, оригиналы источников, цитаты и замечания Pro; можно исправить данные, заказать проверку и опубликовать конкретную версию. Сервис `crimap-admin.service` слушает только `127.0.0.1:8083`, Nginx направляет к нему `/admin/`. Настройки и хеш токена: `/etc/crimap/admin.env`. Публичный сайт продолжает работать на порту 8082.

- [План и состояние реализации](docs/backend/PLAN.md)
- [Контракт всех полей карточек](docs/backend/CONTRACT.md), машинные схемы — `contracts/v2/`
- [Архитектура, модели и расписание](docs/backend/ARCHITECTURE.md)
- [Запуск, проверка, публикация и файлы предложений](docs/backend/OPERATIONS.md)
- Инструкции моделей — `backend/prompts/`; каталог источников — `backend/source-catalog.json`.

Служба сборщика: `crimap-collector.service`; приватная БД: `/srv/crimap/data/collector.sqlite`; предложения моделей: `/srv/crimap/data/field-requests.md`. Ключ DeepSeek хранится в `/etc/crimap/collector.env`. Внешний поиск включится после добавления `BRAVE_SEARCH_API_KEY`; без него работают прямые источники. Новые автоматические данные сначала сохраняются в черновики, не заменяя существующие публичные карточки.

## SSH и сервер


Порт `22`, имя сервера `vencar-main`, Ubuntu 24.04.2 LTS. Пользователь `vencar` имеет `sudo`. Пароль вводится отдельно; пароли и приватные ключи не хранятся в репозитории.

В терминале агента на Windows интерактивная передача пароля через OpenSSH ранее не сработала. Проверенный запасной способ — Python/Paramiko с паролем через стандартный ввод, без записи в файл. Ключ сервера проверяется по `~/.ssh/known_hosts`; отключать проверку не требуется. Обычная команда SSH у владельца работала.

## GitHub и существующий SSH-доступ

- На компьютере `origin`: `https://github.com/Fedorovvn/crimap.git`.
- На сервере `origin`: `git@github.com:Fedorovvn/crimap.git`.
- Репозитории имеют общую историю и ветку `main`.

Первый push выполнен с сервера через существующий SSH-ключ системного пользователя **`wannascale`**. GitHub распознал его как аккаунт **`Fedorovvn`**. Ключ не копировался в проект. У пользователя приложения `crimap` собственного GitHub-ключа пока нет.

Сохранённая HTTPS-авторизация на компьютере при проверке не работала. Для прямого `git push` с компьютера нужно заново авторизоваться. До этого используется перенос коммитов на сервер через `git bundle`, затем отправка через существующий SSH-доступ.

Если подготовленные коммиты уже находятся в `/srv/crimap/app`, отправить их можно так:

```sh
sudo -u wannascale env GIT_SSH_COMMAND='ssh -o BatchMode=yes -o StrictHostKeyChecking=yes' \
  git -c safe.directory=/srv/crimap/app -C /srv/crimap/app \
  push ssh://git@github.com/Fedorovvn/crimap.git main:refs/heads/main
```

`safe.directory` действует только для этой команды и конкретного каталога. Явный URL позволяет отправить изменения без изменения настроек других проектов.

Проверка опубликованного коммита:

```sh
sudo -u wannascale env GIT_SSH_COMMAND='ssh -o BatchMode=yes -o StrictHostKeyChecking=yes' \
  git ls-remote git@github.com:Fedorovvn/crimap.git refs/heads/main
```

На этом VPS есть независимые проекты: Vencar использует Bitbucket (`vencars`), Wannascale — GitHub (`Vicfirt/Wannascale-main-site`). Их конфигурации и ключи для обновления Crimap менять не требуется.

## Единый порядок работы: компьютер → GitHub → сервер

1. Изменять исходники в локальном проекте и проверять результат локально.
2. Выполнять проверки, соответствующие изменению, и сохранять изменения коммитом.
3. Отправлять ветку `main` в GitHub. Пока локальная HTTPS-авторизация не обновлена, передавать коммиты через `git bundle` на сервер и отправлять существующим SSH-ключом.
4. Переносить на сервер именно эти коммиты, без ручного редактирования второй независимой копии. Перед обновлением проверять `git status`; применять `merge --ff-only`, не перезаписывая чужие изменения.
5. Для изменения приложения сохранять резервную копию данных и предыдущей версии, затем устанавливать зависимости, собирать VPS-версию и перезапускать `crimap.service` по инструкции [DEPLOYMENT.md](DEPLOYMENT.md). Для изменения только документации пересборка и перезапуск не нужны.
6. Проверять опубликованный коммит, состояние службы и сайт. GitHub и сервер должны использовать согласованную версию кода.

Push сам по себе не запускает сборку. GitHub Actions, webhook и автоматическое скачивание коммитов сейчас не настроены.

## База данных

**На сервере есть отдельная постоянная SQLite-база** `/srv/crimap/data/incidents.sqlite`. Это рабочая база сайта. В ней хранятся события, источники, хронология, фотографии (ссылки и описания), участники, версии и правовая информация.

При первой публикации перенесён согласованный снимок локальной базы с двумя событиями. Локальная база разработки находится в `.wrangler/state`; далее эти базы независимы и автоматически не синхронизируются.

- Файлы базы не входят в Git и не заменяются при отправке исходников.
- Новые рабочие данные должны сохраняться в серверную базу.
- Изменения схемы описываются SQL-миграциями в `drizzle/` и применяются отдельно после резервного копирования.
- Нельзя заменять серверную базу старым локальным снимком при деплое.
- SQLite может использовать соседние `-wal`/`-shm` файлы; резервную копию работающей базы нужно делать через SQLite backup API, а не простым копированием основного файла.

Подключение задаёт `DATABASE_PATH` в службе systemd. VPS использует `db/sqlite-binding.mjs` — адаптер используемых операций D1 поверх SQLite Node.js.

## Автоматическая подготовка и архив

Flash выполняет короткий отбор сомнительных статей, извлечение, сравнение событий, выбор фотографий из прочитанных источников, черновые переводы. Pro выполняет финальную редактуру подготовленной карточки и всех переводов. Бесплатный фильтр использует расширяемые венгерские основы и выражения из `backend/triage-signals.mjs`: положительный признак защищает статью от автоматического отсева, а отсутствие слов о тяжести не доказывает незначительность ДТП. Неясные случаи проверяет Flash. Повторные неизменившиеся документы не требуют модели.

Адрес сопоставляется с OpenStreetMap через Photon с кешем, ограничением частоты и проверкой района. При неоднозначности сохраняется честная точность «район»/«город». Фото выбираются по ссылкам и описаниям в прочитанной статье; это не визуальное распознавание и не поиск по всему интернету. Существующие фотографии сохраняются при обновлении. В редакторе новое событие и обновление текущего отмечаются отдельно, с кнопками «Опубликовать» / «Обновить на сайте».

При финальной проверке Pro может уточнить неточную геометку по оригинальному тексту: название остановки, станции, здания или другого ориентира. Модель запрашивает до двух поисков по дословно процитированным названиям, получает реальные результаты Photon и выбирает один из них либо сохраняет приблизительное место. Координаты не генерируются моделью; для остановок/ориентиров используется `location.precision=landmark`. Цитата, ссылка OpenStreetMap и обоснование сохраняются в `preparation.locationReview`/`geocoding`. Изменение создаёт новую редакцию, Flash обновляет переводы, затем Pro повторно проверяет готовую карточку. Публикация остаётся ручной. Повторы геопоиска кешируются, прогресс сохраняется при сетевых сбоях, все вызовы моделей остаются в текущем бюджете кампании/суток.

Разовый архивный обход: публикации **26 июля — 26 сентября 2026**, общий потолок моделей **$10** на весь обход, включая Pro (увеличен на $5 27 сентября). Лимит изменяется в редакторе в разделе «Архивный обход и бюджет». Обычный сбор отдельно ограничен $0.50/сутки UTC. Архивы подключены у BRFK и Kékvillogó; текущие источники перечислены ниже в разделе «Постоянный сбор». Остальные записи каталога не считаются подключёнными. Период, состояние обхода, расходы и охват источников видны в редакторе.

## Языки и раздел пропавших

RU / EN / HU переключают весь публичный интерфейс, даты и тексты опубликованных карточек; выбор сохраняется в браузере и параметре `lang`. Переключатель пропавших удалён; `missing-person` временно исключён из сбора и публичной ленты. Публикация только через редактора.

Pro проверяет английскую карточку по оригиналам; затем Flash готовит RU-перевод и EN/HU-словари отображения текущей RU-редакции в приватной таблице `site_translations`. Публикация переносит только переводы показанных полей в публичную `incident_metadata`, вместе с той же редакцией. Оригинальные HU-документы и цитаты не изменяются. Для уже опубликованных записей есть `localize-public`: команда добавляет языковые версии текущего публичного текста, не публикуя черновики.


## Обработка и редактор — 27 сентября 2026

Новый порядок: бесплатные правила → короткий Flash-фильтр темы → краткая идентификация и проверка дублей Flash → полное извлечение и объединение → дополнительные источники (при подключённом поиске), геометка и фотографии → проверка содержания Pro → переводы Flash RU/EN/HU → ручная публикация. Повтор без новых фактов завершается до полной сборки. Сравниваются даты происшествия и названия/координаты места, а не одинаковость категории; Flash подтверждает совпадение, правила сами ничего не объединяют. Пропавшие временно исключены из сбора. Обычный пожар автомобиля без значимых последствий отбрасывает короткий фильтр; нападения, ограбления и необычные опасные ДТП сохраняются.

`node backend/cli.mjs deduplicate --limit 30` объединяет ранее накопленные дубли на Flash. Сохраняется опубликованная идентичность, источники объединяются, исходные записи остаются с `merged_into`. Материальные дополнения становятся новой версией для Pro и публикации, не переписывают сайт автоматически. На повторных запусках модельный кеш предотвращает оплату неизменённых сравнений.

Кнопка «Удалить с сайта» скрывает опубликованную карточку через `incident_metadata.hidden`; источники и история остаются, повторная публикация восстанавливает прежний ID/URL. «Снятые с сайта» доступны через фильтр. Бюджет можно изменить рядом с расходами: резерв незавершённых запросов входит в потраченное; лимит ниже этой суммы запрещён. Увеличение возобновляет остановленные по бюджету задания.

Справочник `backend/institution-addresses.json` связывает известные организации с официальными адресами; адрес повторно проверяется на официальной странице перед поиском реального объекта карты. Это не универсальный поиск адресов всех организаций. Произвольные координаты из памяти модели запрещены. Поиск дополнительных публикаций пока зависит от подключённого поискового провайдера; сохранённые источники доступны без него.


## Постоянный сбор и полнота карточек — 27 сентября 2026

На VPS включены `crimap-collector.service` и отдельный `crimap-discovery.timer`. Таймер каждую минуту запускает только бесплатные задания обхода, независимо от очереди и бюджета моделей. BRFK, общая полицейская лента/ДТП, OKF и MÁVINFORM проверяются раз в 5 минут; Kékvillogó, Bp-i Autósok, Telex и Index — раз в 10 минут; прокуратура — раз в 30 минут. Активный набор: `LIVE_SOURCE_IDS` в `backend/sources.mjs`, на сервере явно задан `COLLECTOR_SOURCES`. Первичное подключение берёт публикации последних 48 часов. Уже известные события проверяются отдельно по согласованной возрастной шкале шедулера.

RSS читается целиком, без старого ограничения на три верхних записи. `feed_entries` сохраняет отпечаток записи; неизменные записи повторно не направляются в обработку, изменения заголовка/даты/анонса допускают повторное чтение. Для тихих правок тела статьи остаётся переобход связанных источников события. `source_polls` и аудит `feed-polled` сохраняют время успешного опроса, число записей и отсеянных/поставленных в очередь материалов. Пустая RSS OKF наблюдается отдельно: при проверке и карта была пустой; полнота оперативного покрытия OKF пока не подтверждена. Facebook/Telegram и BKK API без подключения не выдаются за работающие адаптеры.

После объединения и до геометки/финальной Pro-проверки Flash выполняет `details`: сверяет полные тексты со всеми участниками, дополняет заметки о действиях, травмах и задержании, сопоставляет явно названную квалификацию с проверенным каталогом законов. Возвращает только участников, контекст, право и их цитаты: не может изменить координаты или заголовок. Отчёт о полноте/причине отсутствия права сохраняется в `preparation.detailCompletion`. Если подходящего состава нет в каталоге — запрос `legal.catalog.*` в существующий список предложений. Числовую статью в новости требовать не нужно: привязка по квалификации помечается `editorial`. Правовой блок обязательно связан с соответствующим подозреваемым; санкции не назначаются потерпевшим, взрослые диапазоны не применяются к несовершеннолетним. Flash готовит переводы; Pro проверяет выводы и все языковые версии по первоисточникам, сама исправляет итог; затем ручная публикация.

Текущий архивный бюджет хранится в БД и меняется пользователем в админке; цифры в исторических абзацах README не должны перезаписывать это значение. Обычные новые публикации по-прежнему используют отдельный лимит $0.50/сутки UTC. При достижении потолка платная обработка ждёт следующего дня, бесплатный сбор продолжает пополнять очередь.

Архивные повторные проверки, исправления и переводы наследуют `campaignId` события, включая запуск из редактора и CLI. Исчерпание суточного бюджета не останавливает архив: у него собственный общий потолок в `campaigns.budget_usd`. Новый поток и регулярный переобход явно передают `budgetScope=daily`, чтобы новая цепочка не забирала деньги у исторического обхода. Повтор архивной работы возобновляет завершённую кампанию с прежним лимитом; увеличение лимита автоматически не выполняется.

После исправления схем review/repair однократная команда `node backend/cli.mjs recover-archive <campaignId>` восстанавливает незавершённые архивные карточки и упавшие статьи с аудитом. Она не публикует новости, не меняет лимиты и прежние расходы, не будит дневную очередь. Историческую принадлежность без `campaign_id` восстанавливает только по статье, действительно поставленной в очередь этим обходом. Задания старого исправления теперь направляются в финальный редактор Pro. Отсутствие даты больше не пропускает Pro молча; публикация по-прежнему требует подтверждённой даты. Честное приближение или отсутствующая в каталоге статья сами по себе не повод гонять карточку по кругу.

## Финальный редактор Pro

После подготовки Flash создаёт черновики RU/EN/HU. Затем `review` получает карточку, переводы и дословные абзацы источников: начало статьи, подтверждающие цитаты и соседний контекст, релевантные сведения об участниках/месте/последствиях. Полные оригиналы остаются в БД для технической проверки цитат. Для коротких статей передаётся весь текст. Метка `excerpted` сообщает модели, что часть текста пропущена.

Pro сама возвращает исправленный английский контракт (если изменён), изменения русского текста и английских/венгерских переводов. Новые и изменённые поля требуют полных переводов; устаревшие переводы не переносятся молча. Перед сохранением проверяются все цитаты, схема, связи участников и статей, каталог законов, геометка, покрытие переводов и числа. Черновое несовпадение чисел передаётся Pro для исправления, но в финальную версию не допускается. Исправления, переводы, подготовка и успешная проверка сохраняются одной транзакцией. После Pro Flash не переписывает результат. Подтверждать отдельные правки не нужно: владелец выбирает готовую новость и нажимает «Опубликовать» или «Обновить на сайте».

Неподтверждённые факты модель не придумывает. Неразрешённый существенный конфликт, отсутствие подтверждаемой даты/геометки или техническая ошибка оставляют карточку неопубликованной; это не очередь на подтверждение правок владельцем. Все этапы архивной карточки используют её архивный бюджет. Архивный и суточный бюджеты не складываются и автоматически не увеличиваются.

## Сравнение обновления с публикацией

Для уже опубликованной новости редактор открывает вкладку «Изменения»: фактическая версия с сайта слева, предлагаемый результат справа. Добавления, замены и удаления подсвечиваются по словам. Сравниваются основной текст, категория и статус, даты, координаты/точность, участники, хронология, источники, фотографии с атрибуцией, контекст, право и переводы. Технические ID строк, порядок ключей JSON и reviewStatus не создают ложных отличий. Участники и другие записи с ключами сравниваются по ключам, а не позициям в массиве.

`publication-comparison.mjs` читает согласованный снимок из публичной SQLite и строит проекцию результата публикации. Это бесплатное детерминированное сравнение, не рассказ модели о собственных правках. Pro получает `currentPublication` и `proposedPublicationChanges`, учитывает ранее опубликованные сведения и возвращает русское `publicationSummary` об окончательном обновлении, включая причины значимых удалений. Комментарий модели показывается отдельно от точных отличий. Опубликованный текст не считается независимым доказательством.

Проверка хранит `publicationBaseline` — отпечаток реальной публикации. Изменение публикации во время Pro-проверки требует нового прохода. Опубликовать новую редакцию без сравнения с актуальной публичной версией нельзя. Отпечаток входит и в подтверждение публикации в админке, поэтому устаревшее открытое сравнение не разрешит заменить более новую публикацию. Отдельного подтверждения каждой правки нет; владелец по-прежнему выбирает публикацию всего обновления одной кнопкой.


В блоке архивного обхода сохранение бюджета и продолжение обработки разделены: увеличьте общий лимит, нажмите «Сохранить бюджет», затем «Продолжить». Кнопка возвращает в очередь только приостановленные задания выбранного обхода, сбрасывает их счётчик попыток и показывает количество возобновлённых заданий. Выполненные задания, текущие запросы, ошибки других этапов и суточный поток не перезапускаются; лимит автоматически не увеличивается. Повторное нажатие не создаёт новых заданий. Число заданий на паузе видно рядом с бюджетом.


Отметки редактора хранятся в `events.editorial_mark` (`normal`, `uninteresting`, `priority`) и сохраняются между устройствами и редакциями события. В карточке доступны «Неинтересно» и «В приоритетные», повторное нажатие снимает отметку; отметки взаимоисключающие. Фильтр «Мои отметки» по умолчанию скрывает неинтересные и позволяет показать их снова или оставить только приоритетные. Сортировка «Приоритетные · затем новые» поднимает отмеченные карточки, внутри групп сортирует по дате. Фильтр сохраняется вместе с остальными настройками, «Сбросить» возвращает скрытие неинтересных. Отметки не меняют публичную карточку и её редакцию. «Неинтересно» отменяет задания сборщика и регулярные проверки; приоритет поднимает подготовку и Pro в очереди.


### Редактор управляет обработкой событий

«Неинтересно» отменяет queued/running/paused/failed задания конкретного события (`cancelled`), освобождает аренду и выключает регулярную перепроверку. `Store.enqueue` и выбор задания повторно проверяют отметку. Активная работа проверяет остановку перед следующими вызовами моделей и сохранением результата; уже отправленный запрос может завершиться и оплачивается по фактическому расходу, но его результат не продолжает обработку. Возобновление архивного бюджета не восстанавливает отменённые задания.

Причины выбираются из `backend/admin/interest-reasons.mjs`; несколько тегов и комментарий до 2000 символов хранятся в `editorial_reasons` / `editorial_note`, изменения — в аудите. Это решение по конкретному происшествию, не автоматическое обучение общему фильтру. Причины не передаются в сравнение как инструкция отвергать похожие новости.

Неинтересные события участвуют в подборе кандидатов и дешёвом сравнении Flash по фактическому происшествию, включая опубликованные и скрытые карточки. Подтверждённое repeat/update сохраняется в `ignored_updates` со ссылкой, версией источника и объяснением совпадения; извлечение полной карточки, фотографии, переводы и Pro не запускаются. В админке видны «Обновления без обработки». Совпадение категории или соседнего адреса не является достаточным. При возврате из неинтересных эти источники ставятся на повторный разбор, регулярная проверка и незавершённая подготовка снова разрешены.

«Приоритетное» ставит незавершённую подготовку в очередь и поднимает всю её цепочку (сбор, подготовку, Pro, переводы) перед обычными заданиями. Уже готовая карточка не требует повторного платного Pro. Активный запрос другого события не прерывается. Суточный и архивный бюджеты соблюдаются; при исчерпанном архиве приоритет ждёт сохранения бюджета и кнопки «Продолжить». При объединении дубликатов неинтересная отметка и её причины сохраняются, задания обоих событий останавливаются; приоритет также переносится на основную карточку.


### События без даты

Событие без установленного дня происшествия сохраняется со статусом `awaiting-date`. Подготовка фотографий, геометки, переводов и проверка Pro приостанавливаются; публикация запрещена. Приоритет не обходит эту паузу или лимит бюджета. В редакторе есть фильтр «Ожидают даты» и кнопка «Уточнить дату».

Задание `resolve-date` использует Flash только для даты по сохранённым источникам. Дата публикации не подставляется вместо даты события. Достаточно подтверждённого календарного дня с точностью `day`; относительные даты требуют надёжной даты публикации и часового пояса Будапешта. Результат содержит точную цитату и источник. Если даты нет, оригиналы сохраняются, раз в сутки перечитываются до трёх известных источников. Неизменившийся набор текстов не отправляется в модель повторно. При настроенном поисковом API дополнительно проверяются до трёх результатов одного поиска на версию события; совпадение события проверяет Flash. Все платные вызовы учитываются в соответствующем архивном или суточном бюджете.

После установления даты создаётся новая версия и автоматически продолжается подготовка. Новые материалы могут сопоставляться с отложенными событиями по месту, характерным словам заголовка или номеру дела; совпадение подтверждает модель. «Неинтересно» останавливает и уточнение даты.

На десктопе редактор занимает высоту окна: фильтры расположены над независимо прокручиваемыми списком событий и открытой карточкой; полосы прокрутки скрыты. Фильтры раскрываются по нажатию, а на невысоких экранах их панель тоже можно прокрутить. На публичном сайте между карточками и полосой прокрутки оставлен зазор, высота карты ограничена так, чтобы внизу был виден верх статьи.


### Редакционная тематика и полезность фотографий — 27 сентября 2026

Общие инструкции для дешёвого отбора, идентификации и извлечения находятся в `backend/prompts/editorial-scope.md`. Основная тема — внезапная опасность для человека в повседневной жизни, включая нападение знакомого/партнёра, ограбление, проникновение в жильё и существенные ДТП. Животные, промышленные/химические аварии (включая утечку хлора с госпитализациями), наркотические дела без отдельного подходящего происшествия, рейды и ведомственная рутина, экономические дела, мелкий имущественный ущерб и добровольный экстремальный спорт вне тематики. Упоминание наркотиков, животного или рейда не исключает отдельное нападение на человека. Неосторожность потерпевшего не означает согласия на опасность. Пограничные ДТП, в том числе перевернувшаяся скорая с пострадавшими, продолжают поступать на редакционное решение. Отказ от конкретной карточки не обучает автоматический запрет категории. Новые причины доступны в диалоге «Неинтересно».

Однозначные нападения животных и утечки на химическом предприятии отсекаются бесплатно по заголовку. Неоднозначный контекст наркотиков/рейдов/животных/экстремальных занятий направляется Flash до разрешающих зелёных флагов: слова «оружие», «эвакуация» и «необычный» не обходят тематическую проверку.

В подготовке фото сначала бесплатно исключаются явные логотипы и заглушки по URL/подписи. Затем `media-review` передаёт выбранные изображения непосредственно в `deepseek-flash` как `image_url` с `detail=low`, группами до трёх. Отвергаются гербы, общие полицейские иллюстрации, реклама, сток и картинки с неустановленной связью с событием. Реальное фото с маленьким водяным знаком допустимо. Решения сохраняются в `preparation.mediaReview`; ссылки и права проверяются отдельно. Pro получает эти решения и не может вернуть неподтверждённые изображения. Снимки в уже опубликованных карточках пересматриваются при подготовке очередной версии, без автоматической перепубликации.

Визуальная проверка использует прежний бюджет задания (архивный или суточный), резервирует до 1024 входных токенов на изображение и учитывает фактические токены ответа API. Повтор того же запроса берётся из кэша; кэш хранит исходную JSON-форму ответа, чтобы валидатор мог повторно её прочитать. Оценка расходов консервативная, по пиковым тарифам. Документация: https://api-docs.deepseek.com/guides/vision/ и https://api-docs.deepseek.com/quick_start/pricing/.

### Обязательная правовая проверка и взаимодействие с картой — 27 сентября 2026

Pro обязан вернуть `legalCoverage`: итог, конкретную причину на русском и отдельный результат для каждого подозреваемого. Сервер отклоняет пропущенных участников и несоответствие наличию правовых блоков. Админка показывает этот отчёт, при его отсутствии — предварительный результат Flash либо честное сообщение, что причина ещё не проверена. Старые публикации не перепубликуются автоматически. Политика `backend/prompts/legal-coverage.md` подключается к извлечению, дополнению, объединению, исправлению и Pro. Номер параграфа в новости не обязателен: достаточно поддержанного источником состава. Условные сопоставления `possible` допускаются только для каталожных записей с `factBasedMapping` и выполненными условиями; отсутствие фактов или подходящей проверенной нормы объясняется, а не заполняется догадками. Начальное разрешённое сопоставление — основной состав умышленного причинения вреда со сроком заживления свыше восьми дней (§ 164 (3)); госпитализации или слова «тяжёлый» недостаточно. Норма перепроверена в NJT.

На десктопе наведение на карточку выделяет её точку красным, выбранная точка бордовая. Наведение на карту центрирует карточку только внутри списка и подсвечивает фон, не меняя выбранную статью. По умолчанию открыт весь период; смена периода сбрасывает фокус камеры на отдельную точку и показывает все отфильтрованные точки.

Финальная проверка Pro: список изменений передаётся как компактный индекс путей (значения уже есть в обеих версиях карточки), чтобы не превышать лимит 160 000 символов. Ожидание ответа Pro — до 240 секунд; Flash — до 90. Бюджет резервируется до запроса, включая случаи сетевого таймаута.
