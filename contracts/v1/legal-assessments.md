# Правовая квалификация и возможные санкции

Контракт 1.2: `event.legal[]`. Данные сохраняются в `incident_legal` и отображаются внутри карточки соответствующего подозреваемого (или осуждённого), по точному совпадению `participantKey`. Значок весов и название правонарушения образуют первую строку; ниже санкция выровнена по левому краю основного текста карточки, а ссылки на статьи — по правому. Название имеет обычный цвет и вес шрифта, статьи выделены цветом остальных ссылок сайта без подчёркивания, жирным выделен только срок. Пояснение о справочном сопоставлении и решении суда перенесено в tooltip у иконки информации, доступный при наведении и фокусе с клавиатуры. Имя участника и заголовок блока повторно не выводятся. Пустой массив скрывает блок.

Записи без `participantKey` или с неизвестным ключом сохраняются, но не приписываются человеку и не показываются в карточках. Сведения о группе не копируются автоматически в индивидуальные карточки после её разворачивания; для этого нужны отдельные проверенные привязки. Потерпевшему правовой блок не назначается.

Для каждой квалификации есть два основания: публикация о конкретном деле и текст закона. Официальное сообщение о подозрении не устанавливает виновность. Если ведомство не называет номер и часть статьи, сопоставление помечается как справка редакции.

## Поля

| Поле | Тип / значения | Значение |
| --- | --- | --- |
| `key` | string | Стабильный ключ квалификации внутри события |
| `jurisdiction` | `HU` | Право Венгрии |
| `subjectLabel` | string | К кому относится: например, «40-летний подозреваемый» |
| `participantKey` | string, необязательно | Ключ конкретного участника, когда соответствие установлено |
| `offense` | string | Название предполагаемого правонарушения на языке интерфейса |
| `qualification` | `official`, `reported`, `possible` | Сообщено ведомством; сообщено СМИ; возможная квалификация |
| `stage` | `investigation`, `charged`, `trial`, `judgment` | Следствие, обвинение, суд, судебное решение |
| `source` | object | Публикация о деле: `label`, HTTP(S) `url`, `kind: official / media`, `publishedAt` |
| `statuteMatch` | `source-explicit`, `editorial` | Точная статья названа источником либо сопоставлена редакцией |
| `statutes` | object[], минимум 1 | Закон и статья; можно несколько норм, например о составе и о покушении |
| `penalties` | LegalPenalty[] | Санкции выбранной нормы; пусто, если достоверный диапазон не установлен |
| `condition` | string | Условия применения: основной состав, версия следствия, неуточнённая часть статьи и т. п. |
| `reviewStatus` | `pending`, `approved` | Проверка привязки к делу, нормы, редакции закона и условий |
| `checkedAt` | date-time | Время проверки справки |

Все поля обязательны, кроме `participantKey`. Сведения о разных подозреваемых хранятся отдельными объектами. Нельзя назначать всем участникам группы одну квалификацию только из-за совместного задержания.

### Норма закона: `statutes[]`

| Поле | Значение |
| --- | --- |
| `code` | `criminal` — уголовное право; `petty-offense` — правонарушения; `administrative` — административное законодательство |
| `act` | Оригинальное обозначение акта, например `2012. évi C. törvény` |
| `section` | Точная статья, часть и пункт |
| `url` | HTTP(S) ссылка на текст нормы |
| `versionDate` | Дата редакции закона, `YYYY-MM-DD` |

Не подставляем российские кодексы. Для Венгрии используются [Уголовный кодекс — Btk.](https://njt.jog.gov.hu/jogszabaly/2012-100-00-00) и, когда применимо, [закон о правонарушениях — Szabs. tv.](https://njt.jog.gov.hu/jogszabaly/2012-2-00-00); административные санкции могут определяться другими актами. Во втором случае нужно указывать конкретный акт, а не придумывать единый «административный кодекс».

### Санкции: `penalties[]`

| `kind` | Остальные поля | Отображение |
| --- | --- | --- |
| `imprisonment` | `min?`, `max`, `unit: years / months` | Диапазон или верхний предел лишения свободы |
| `life-imprisonment` | нет | Пожизненное лишение свободы |
| `fine` | `min?`, `max`, `unit: HUF` | Штраф в форинтах |
| `detention` | `min?`, `max`, `unit: days` | Арест |
| `community-service` | `min?`, `max`, `unit: hours` | Общественные работы |
| `driving-ban` | `text` | Проверенная формулировка ограничения права управления |
| `other` | `text` | Иная санкция с основанием в приложенной норме |

`min` неотрицателен, `max` положителен, `min ≤ max`. Отсутствие нижнего предела в записи не означает, что закон допускает нулевой срок. Несколько санкций показываются отдельно, не суммируются; альтернативность или совместное применение нужно разъяснить в `condition`.

## Правила для будущего парсера

1. Извлечь формулировку квалификации и её процессуальную стадию из публикации. Задержание, ходатайство о заключении под стражу, обвинение и приговор различаются.
2. Привязать её к конкретному человеку или явно описанной области события. Не угадывать соответствие по порядку карточек.
3. Найти норму в официальном законодательном источнике и сверить редакцию, применимую к дате события. Учесть правила действия закона во времени; просто текущей версии может быть недостаточно.
4. Сохранять предполагаемое сопоставление как `possible` и `pending`, если официальной квалификации нет. Модель может предлагать норму для проверки, но не назначает виновность, статью или срок автоматически.
5. Проверить часть статьи, признаки состава, возраст участника, стадию и условия санкции. Для несовершеннолетних нельзя механически брать диапазон для взрослых. Если данных не хватает, оставить `penalties: []` либо показать условную справку с точным пояснением.
6. После проверки сохранить `approved`. Изменение квалификации требует новой проверки и обновления; будущий парсер должен сохранять историю ревизий.

В интерфейсе используется двухстрочная композиция: «правонарушение», затем санкция слева и статьи справа. Условия применения и редакция закона доступны в подсказке ссылки; полное пояснение сохраняется в контракте. Сообщённая источником квалификация служит ссылкой на публикацию; неофициальные версии имеют явную подпись. «Ему грозит до…» без уточнения применимой нормы и основания не генерируется. При `stage: judgment` здесь всё равно указана санкция закона: назначенный судом срок потребует отдельного поля приговора.

## Что уже работает

Хранение, серверная проверка структуры, фильтр публикации, вывод ссылок и санкций. JSON Schema и TypeScript описывают новые поля. Числовое соотношение `min ≤ max` проверяется runtime-схемой отдельно от JSON Schema. Новые данные без проверки не показываются; ссылка СМИ не может иметь `qualification: official`.

Примеры наполнены по прочитанным сообщениям [BRFK об Akácfa utca](https://www.police.hu/hu/hirek-es-informaciok/legfrissebb-hireink/bunugyek/emberoles-erzsebetvarosban-a-nyomozok-mindket) и [BRFK о Soroksári út](https://www.police.hu/hu/hirek-es-informaciok/legfrissebb-hireink/kozlekedesrendeszet/orizetben-a-soroksari-uti-halalos), с редакцией Btk. от 26 августа 2026 года, доступной при проверке 26 сентября. Квалификация взята из полиции; сопоставление с параграфами выполнено для справки и так обозначено в UI. Данные об административных нарушениях в эти события не добавлялись.

Автоматический поиск закона, проверка официальных доменов, редактор рассмотрения, история правок и парсер ещё не подключены. Тип источника и `reviewStatus` заполняются при проверке; наличие флага само по себе не является автоматическим юридическим фактчекингом.
