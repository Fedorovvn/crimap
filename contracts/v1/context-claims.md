# Сведения, версии и происхождение утверждений

Добавлено в работающий интерфейс и контракт 1.1. Один и тот же тип `ContextClaim` описывает версию о событии и сведения о конкретном участнике. Хранится в `event.context[]`. Источник и подтверждение задаются отдельно для каждого утверждения: общий бэдж события не делает все дополнительные сведения официальными.

## Поля

| Поле | Тип | Обязательно | Значение |
| --- | --- | --- | --- |
| `key` | string | Да | Стабильный ключ утверждения внутри события |
| `subject` | object | Да | `{kind: "event"}` или `{kind: "participant", participantKey: "…"}` |
| `subject.participantKey` | string | Для участника | Ссылка на исходный `participants[].key`, не на номер карточки после разворачивания группы |
| `topic` | enum | Да | Тема, перечислена ниже |
| `text` | string | Да | Сам текст с авторством: «По сообщению…», «Со слов…», «Предположительно…» |
| `origin` | `source`, `model` | Да | Пересказ источника либо собственный вывод модели |
| `verification` | enum | Да | Степень подтверждения конкретного утверждения |
| `reviewStatus` | `pending`, `approved` | Да | Проверены ли источник, привязка к человеку/событию и формулировка для показа |
| `evidence` | object[] | Да | Не менее одного источника / основания |
| `asOf` | string, date-time | Да | Дата оценки актуальности сведения |
| `rationale` | string | Для гипотезы модели | На каких опубликованных данных основан вывод |

Каждый элемент `evidence`:

| Поле | Тип | Обязательно | Значение |
| --- | --- | --- | --- |
| `kind` | `official`, `media`, `eyewitness`, `social` | Да | Официальный источник, СМИ, очевидец, публикация в соцсети |
| `label` | string | Да | Название источника, отображаемое ссылкой |
| `url` | HTTP(S) URL | Да | Конкретная публикация |
| `attribution` | string | Нет | Кто именно сообщил: например, «со слов знакомого погибшего; имя не раскрыто» |
| `relation` | `supports`, `disputes`, `background` | Да | Подтверждает наличие такого сообщения, оспаривает его или даёт лишь фон |

`supports` означает, что источник действительно содержит утверждение, а не что оно независимо доказано. Статья таблоида, пересказывающая слова очевидца, хранится как `kind: "media"`, с очевидцем в `attribution`. Прямой пост Facebook — `social`. Тип источника должен определяться по проверенному каталогу и самой публикации, а не по слову «официально» в её тексте.

## Перечисления

`topic`:

- `motive` — возможный мотив, сообщённый источником;
- `circumstances` — обстоятельства;
- `citizenship` — гражданство по сведениям источника;
- `occupation` — занятие / род деятельности, включая занятия в прошлом;
- `visitor-status` — турист, временный посетитель и другие обстоятельства пребывания;
- `housing-status` — жилищная ситуация;
- `appearance` — опубликованное описание очевидца, без автоматического определения происхождения по внешности.

`verification`:

- `unverified` — не подтверждено независимо;
- `corroborated` — есть независимое подтверждение, его источники должны быть перечислены;
- `disputed` — есть противоречия; нужно приложить и оспаривающий источник;
- `retracted` — сведения отозваны; карточка сохраняет явную отметку исправления.

Тип источника не равен достоверности факта. Официальное сообщение может само содержать предварительную версию. Газета может точно цитировать ведомство, но до проверки оригинала остаётся публикацией СМИ. Перепечатки одной новости не дают независимого подтверждения.

## Отображение

Сведения отображаются обычными абзацами под описанием события или человека, без вложенных карточек, бэджей и дополнительных заголовков. Упоминания изданий в тексте — ссылки на публикации. Авторство и неопределённость сохраняются в самих формулировках («по сообщению», «со слов», «предположительно»). Происхождение, степень подтверждения и атрибуция доступны в подсказке ссылки; полные данные, включая дату, остаются в контракте. Противоречия, отзыв сведений и гипотезы модели обозначаются явно в тексте.

Источник `official` даёт соответствующую пометку только когда у него `relation: "supports"`. Официальная ссылка, приложенная как фон, не делает неподтверждённые сведения официальными. Для модельного вывода всегда показываются «Гипотеза модели», «Неофициально» и основание вывода.

Версии о гражданстве не устанавливают подтверждённое `profile.citizenship` и флаг. Статус туриста не означает гражданство страны, откуда человек приехал. Слова о внешности не дают основания определять этническую принадлежность, гражданство или личность человека. Неподтверждённые сведения не изменяют автоматически возраст, силуэт, виновность или статус участника.

Контекст группы из 1–4 человек показывается один раз с подписью «О группе», а не приписывается каждому созданному силуэту. Контекст конкретного человека виден только рядом с его ключом; неизвестный ключ не угадывается по имени.

## Гипотезы модели

Модель может формировать объяснимые гипотезы об обстоятельствах события по опубликованным данным. Для вывода в интерфейс нужны `origin: "model"`, `rationale`, источники и `reviewStatus: "approved"`. Они остаются предположениями. Свободное генерирование гипотез и редактор проверки пока не подключены; сейчас реализованы структура, фильтр и отображение.

В текущем фильтре модельные гипотезы разрешены только для `subject.kind: "event"` и `topic: "circumstances"`. Самостоятельные догадки модели о гражданстве, этническом происхождении, личности, бездомности, занятиях, мотивах конкретного человека или его виновности не публикуются. Такие сведения и версии могут передаваться с атрибуцией из реально проверенной публикации через `origin: "source"`. Нельзя выдавать собственную догадку за сообщение источника.

`reviewStatus` — внутренний признак проверки материала, не оценка его истинности: опубликованное утверждение может оставаться `unverified`. Будущий парсер сначала сохраняет новые сведения как `pending`. Для тестового наполнения опубликованные источники были прочитаны и формулировки проверены вручную в ходе этой задачи.

## Реализованная проверка и дальнейшие ограничения

Сервер и UI скрывают `pending`, сведения без ссылок, с пустым текстом или некорректной датой. Для собственного вывода модели также проверяются допустимая тема, область, основание и отсутствие метки независимого подтверждения. У сообщения источника должна быть хотя бы одна поддерживающая ссылка.

JSON Schema проверяет структуру; семантические правила публикации реализованы отдельно в `app/context-model.ts`. Сейчас нет автоматического фактчекинга, проверки независимости изданий, редактора версий или сверки URL с каталогом официальных доменов. До включения автоматического наполнения эти проверки и процесс рассмотрения `pending` должны быть подключены. Новые утверждения не должны перезаписывать историю: следующему этапу парсера потребуется хранение ревизий.
