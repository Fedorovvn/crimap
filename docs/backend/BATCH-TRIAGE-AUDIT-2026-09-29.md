# Проверка пакетного Flash-фильтра, 29 сентября 2026

## Что изменено на сервере

Для поиска новых статей оставлены только **BRFK / police.hu и Kékvillogó**. Настройка `COLLECTOR_SOURCES=police-brfk,kekvillogo` совпадает с `LIVE_SOURCE_IDS` в коде. В очереди проверены две активные ленты; отключены ленты Index, Telex, BpiAutósok, MÁVINFORM, OKF, общевенгерской полиции и прокуратуры. Отменены 12 ожидающих заданий: восемь обходов лент и четыре новые статьи из отключённых лент, ещё не связанные с событиями.

Сохранённые источники не удалены. Поиск дополнительной информации и обновления известных событий могут использовать остальные сайты каталога. Это не доказательство, что две ленты покрывают все будущие происшествия. Произвольные сайты вне каталога текущий загрузчик не поддерживает.

**Пакетная проверка в рабочем пайплайне не включена.** Все описанные ниже обращения — отдельный эксперимент, без изменения карточек, очереди событий и публикаций. Расходы записаны в обычный общий бюджет.

## Устройство теста

Модель `deepseek-flash`, thinking выключен, temperature 0. Выбраны 20 сохранённых статей: источники опубликованных событий, ДТП в ожидании подтверждения гибели, неинтересные редактору и ранее отсеянные материалы. Это целевая проверка пограничных случаев, а не случайная выборка часовой ленты. Несколько статей относятся к одному происшествию.

Одинаковые тексты после существующего `triageExcerpt` отправлены по одному, пачками по пять, по десять и по десять в обратном порядке. Сохранены действующие критерии релевантности. Пакетный протокол требует отдельного решения для каждого ID и ссылок на номера абзацев именно его статьи. Проверяются полнота ID, отсутствие повторов и существование указанных абзацев; формат не доказывает правильность смыслового решения.

Одиночные запросы используют действующий формат с необязательной дословной цитатой. Поэтому сравнивается весь экспериментальный протокол (включая замену цитат номерами), а не только размер пачки.

В первой пробе пакетного формата с буквальными цитатами два из восьми запросов не прошли проверку точности цитаты. В итоговом формате с номерами абзацев все пакеты прошли структурную проверку. Два одиночных ответа также потребовали повторения из-за неточной цитаты; повторения учтены ниже. Начальная ошибка настройки тестового клиента дала HTTP 400 без генерации; её резервы обнулены по конкретным записям, прочие расходы не менялись.

## Решения и логичность

С исходными критериями все три пакетных прогона совпали с итоговыми одиночными решениями **20 из 20**. Перестановка статей не изменила ответы. Однако независимое чтение сохранённых текстов выявило две общие ошибки: ДТП в Gyál (документ 524) и Pirtó (997) модель откладывала до появления сведений о гибели, хотя они вне Будапешта и должны отсеиваться.

Во второй экспериментальной инструкции явно задан порядок: сначала география, затем правило ожидания гибели. В ней прямо названы Gyál и Pirtó. На тех же статьях все три пакетных прогона исправили ровно эти два решения; остальные 18 сохранились. Получилось **20 из 20 ожидаемых решений на этой выборке**. Это настройка и повторная проверка на одних данных, не независимый тест: она не доказывает надёжность на неизвестных географических названиях. Производственные инструкции в рамках этого эксперимента не изменены.

Проверка относится к содержанию конкретной версии источника, а не ко всем известным фактам события. Например, реанимация сама по себе не подтверждает смерть. Решение «пропустить» ещё не разрешает сборку: далее остаются дата, сравнение дублей и остальные проверки. Две статьи про одно убийство должны обе пройти тематический этап, а затем сопоставиться на этапе идентификации.

## Рекомендация перед внедрением

Начать с пачек до пяти статей после бесплатного отсева, с ограничением общего размера текста. Сборщик уже проверяет ленты раз в час: дополнительного часа ожидания для набора полной пачки не нужно. При малом потоке отправлять неполную пачку.

Для каждой статьи нужен самостоятельный результат, а не один ответ «в пачке есть что-то интересное». Невалидные/пропущенные решения следует повторять отдельно, не запускать из-за них повторно все статьи. Неуверенная география не должна автоматически становиться отказом. Перед внедрением приоритет географии стоит проверить на других городах, пограничных адресах и статьях с несколькими местами, которые не использовались для настройки.

Дальнейшие этапы идентификации, поиска дублей и Pro не меняются. Смешивать факты статей в этой пачке запрещено. Переход к пакетам потребует отдельной реализации очереди и теста восстановления после ошибок; текущий файл — исследовательский инструмент.

## Воспроизведение

`backend/batch-triage-audit.mjs` без `--live` только читает базу и показывает выборку. С `--live --out=PATH` делает ограниченные платные запросы и пишет журнал расходов; общий бюджет и дополнительный потолок $0.30 действуют совместно. `--retry-singles` повторяет отсутствующие валидные одиночные ответы из отчёта, `--geo-first` проверяет экспериментальное уточнение на сохранённой выборке. Не запускать эти флаги как обычное задание сборщика.

Полные приватные результаты на сервере: `/srv/crimap/identity-validation/batch-report.json`, первая проба: `batch-report-initial.json` в том же каталоге. Локальная копия: `work/batch-triage-report.json` вне Git. Краткие результаты с ID и ссылками сохранены рядом в `BATCH-TRIAGE-EVIDENCE-2026-09-29.json`; ключей и полных статей там нет.
